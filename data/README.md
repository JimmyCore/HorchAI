# data/

Raw audio, segmented keystrokes, and extracted feature arrays are
**never committed to this repository** (see `.gitignore`). They can be
large, and — more importantly — keystroke recordings are sensitive by
nature even when self-recorded, so this project only versions the *code*
that produces and consumes them, plus small non-sensitive metadata
(labels, timestamps, split assignments).

## Expected layout (local / Google Drive, not git)

```
data/
├── raw/                  # one folder per key, raw multi-press recordings
│   ├── a/take1.wav, take2.wav, ...
│   ├── s/...
│   ├── d/...
│   ├── f/...
│   ├── j/...
│   ├── k/...
│   └── l/...
├── processed/            # segmented single-keystroke .wav or .npy (generated)
└── metadata.csv          # generated by src/dataset.py — safe to commit
```

See `docs/recording_protocol.md` for exactly how to produce `data/raw/`.

## In Google Colab

Since the primary runtime is Colab and the user works mostly from a phone,
`notebooks/horchai_poc.ipynb` supports two ways to get data in:

1. **Direct upload** via the notebook's upload cell (good for a handful of
   files / a quick single-file demo).
2. **Google Drive mount** (recommended for the full Phase 2 dataset —
   upload your `data/raw/` folder to Drive once, then mount it in Colab so
   you don't have to re-upload every session).

Both paths are handled in the notebook; no manual terminal steps needed.
